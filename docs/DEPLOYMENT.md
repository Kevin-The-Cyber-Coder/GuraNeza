# Deployment guide

GuraNeza is deployed on [Render](https://render.com) with a blueprint defined in [`render.yaml`](../render.yaml). The frontend is a static build served from a CDN; the API is a Node web service talking to MongoDB Atlas.

| Service | Type | Default URL |
|---|---|---|
| `guraneza-ja1a` | Static Site (`client/dist`) | <https://guraneza-ja1a.onrender.com/> |
| `guraneza-api` | Node Web Service (`server/`) | <https://guraneza-api.onrender.com> |

---

## 1. Prerequisites

- A MongoDB Atlas cluster (a replica set is required for transactions) with the seed data loaded
- A Render account connected to the GitHub repository
- A strong `JWT_SECRET`
- Optional: a [Resend](https://resend.com) API key for seller invitation emails
- Optional: Cloudinary credentials for image uploads

---

## 2. Create the services

1. In Render, choose **New → Blueprint** and select this repository.
2. Render reads `render.yaml` and proposes both services.
3. When prompted, provide:

| Variable | Required | Notes |
|---|---|---|
| `MONGO_URI` | ✅ | Atlas connection string |
| `ADMIN_EMAIL` | ✅ | Seed/administrator email |
| `ADMIN_PASSWORD` | ✅ | Use a strong value — never reuse the demo password |
| `JWT_SECRET` | ✅ | Generated by `generateValue: true`; keep it secret |
| `CLIENT_URL` | — | Frontend origin allowed by CORS |
| `RESEND_API_KEY` | — | Enables invitation email |
| `CLOUDINARY_*` | — | Enables hosted image uploads |

The blueprint already sets `NODE_ENV=production`, `JWT_EXPIRES_IN=30d`, the API health check (`/api/health`) and the client `VITE_API_URL`.

> If the static site builds from the monorepo root, its build command must install the client workspace explicitly: `npm install --prefix client && npm run build --prefix client`, publishing `./client/dist`.

| Variable | Value |
|---|---|

Vite inlines this value **at build time** — redeploy the static site after changing it.

## 4. SPA routing (required)

Render static sites do not read `client/public/_redirects`. Without a rewrite, URLs such as `/register`, `/shop` or `/admin` return a plain 404.

In the static site → **Settings → Redirects/Rewrites**, add:

| Type | Source | Destination |
|---|---|---|
| **Rewrite** | `/*` | `/index.html` |

Choose **Rewrite**, not Redirect. A redirect changes the address bar to `/index.html`, which React Router does not recognise and renders as its own 404 page.

## 5. Verify the deployment

```bash
# API health
curl https://guraneza-api.onrender.com/api/health

# Catalogue responds
curl "https://guraneza-api.onrender.com/api/products?limit=2"

# Frontend serves the SPA
curl -I https://guraneza-ja1a.onrender.com/
```

Then in a browser:

1. The storefront loads products and images.
2. Deep links work directly (`/shop`, `/track-order`).
3. Sign in as the administrator and confirm `/admin` loads KPIs.
4. Place a test order and track it by order number + email.
5. Submit a seller application and check it appears in the admin review queue.

---

## 6. Database preparation

- Seed **before** the first production use, or create the administrator manually.
- `npm run seed` refuses to run when `NODE_ENV=production`; run it locally against the production URI only if you intend to create demo data.
- Migrations in `server/src/migrations/` run automatically on boot and are safe to re-run.
- Allow Render's outbound IPs in the Atlas network access list (or `0.0.0.0/0` for a demo deployment).

---

## 7. Continuous deployment

- Pushes to `main` trigger a Render deploy for both services.
- `.github/workflows/ci.yml` runs lint, tests and the production build on every pull request and push to `main` / `develop`.
- Keep `main` deployable at all times; promote `develop` through a pull request.

---

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Deep link shows "Not Found" | Missing SPA rewrite | Add the `/* → /index.html` **rewrite** rule |
| CORS error in the console | Frontend origin not allow-listed | Set `CLIENT_URL` on the API service and redeploy |
| `401` immediately after login | `JWT_SECRET` changed between deploys | Sign in again; keep the secret stable |
| API returns 503 on first request | Free instance cold start | Wait for the instance to wake, then retry |
| Images missing after upload | No Cloudinary config and ephemeral disk | Configure Cloudinary for durable storage |
| Invitation email not received | `RESEND_API_KEY` missing | Configure Resend and resend the invitation |

---

## 9. Rollback

Render keeps previous deploys per service. Open the service → **Deploys** → select the last healthy deploy → **Redeploy**. Database migrations are additive, so rolling back application code does not require a data rollback.
